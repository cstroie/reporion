# Decision log

Every architectural decision taken during design, with the reasoning compressed to what a
future maintainer needs. **Do not relitigate these in code.** To change one, change it here
first, note the date, and update the affected spec in the same commit.

Sources: `docs/architecture-storage-index.md`, `docs/architecture-api.md`.

## Storage and identity

| # | Decision | Why |
|---|---|---|
| D1 | Patient name stays in the page path (`{yymmdd}-{name}`) | Biggest driver of daily speed. Compensated: the path never appears in an export, external URL, log line, audit entry (`path_hash`) or AI prompt. Amended 2026-09-27: a report's own exports (print, PDF, ODT) name the patient in the patient block: a report belongs to its patient; the path is still not in them. Amended 2026-10-11 (owner's decision): an export's *file name* is the page path with `-` for `:` (`reports-mri-polimed-261008-name.pdf`) for a signed-in caller, so reports sent to the imaging center are never mixed up; an anonymous export of a public page keeps `{accession or pid}-rev{N}`; the path is still not in the document's content |
| D2 | `current.md` duplicates the newest revision | Reading is the most common operation; it must never require gunzip. ~2× storage on one revision is nothing at 2.4 kB/report. Amended by D54 (2026-10-20): the fast path is the page file `pages/…/{slug}.md`, the archival copy the attic zip's newest entry (was `current.md` and `rev/NNNN.md.gz`) |
| D3 | Correcting a signed report = new revision, signed again; old signed revision stays in history | Simpler than addendum rendering. Consequence: exports embed `rev` + a `/r/{pid}/{rev}` verification link, which becomes the citable document |
| D3b | Signed content can be superseded, never deleted | Legal integrity. Purging a signed page needs an explicit override + audit entry |
| D21 | App-managed history, not git | No auto-commit, no 4 000 git directories. `rev/*.md.gz` + `revlog` *is* the history. Amended by D54 (2026-10-20): the attic zip (`NNNN.md` entries + `revlog.json`) is the history |
| D30 | The DokuWiki H1 (patient name) was lifted to `patient.name` by the importer (removed 2026-10-09; the archive is imported); rendered H1 is the exam title | No identifier inside body text that could be published or sent to a model; also fixes search relevance. Amended 2026-09-26: reports created in the app carry the name as `title` and first `#` heading, `exam_title` holds the exam; the public layout and duplicates drop the name heading (`Support\ReportName`). Amended 2026-09-27: a report's own exports name the patient in the patient block; the signed-in page view drops the name heading too (its header shows the name); every report body is `# name / ## exam / ### sections` (FORMATS.md §11). **Amended 2026-10-13:** the first `#` heading *is* the title (`Support\PageTitle`); `title` in frontmatter is only an optional override, never written for the author, so a report made in the app carries no `title` and its `#` is the name. In an app-shape report (`patient` + `exam_title`) the first `#` is the name heading whatever its spelling, so a corrected heading never reaches a public page or a teaching copy. |

## Index and search

| # | Decision | Why |
|---|---|---|
| D4 | Typed columns for the facet set, `meta_json` for the tail | A generic key/value table makes every faceted query a pile of self-joins |
| D5 | FTS5 with `remove_diacritics 2` | Romanian clinical text is written with and without diacritics by the same person on the same day |
| D28 | Query-time synonym expansion + prefix match on the last token; no stemmer | SQLite has no Romanian stemmer, and the clinical vocabulary is small, closed and yours: synonyms beat a stemmer here |
| D29 | `modality` and `region` are **lists** | A combined CT cerebral + cervical must appear under both. Child tables `page_regions`, `page_modalities`; facets count a page once per value. Phase 12 (2026-09-27): a multi-exam report's `page_regions` also take every exam's regions (`exams[].region`), so a stale top-level list never hides an exam |
| n/a | Index carries `schema_version`; mismatch triggers rebuild | Lets the schema change fearlessly, which matters over years |

| D48 | Report writes are current-format only; reads accept every format (2026-10-15) | **Writes never look back, reads never refuse** (2026-10-15, owner's rule). (1) **Write:** every save of a report (`Storage` → `Support\Exams::normalize()`) writes the newest format only; no code path writes an older shape, a copy for the benefit of an older reader, or a mix. (2) **Read:** every reader accepts every format a report was ever stored in, trying the newest and falling back through older ones to the oldest (`Support\Exams::of()`/`report()` are the one place that knows them). Signed revisions are never rewritten (D3), so old shapes are read for ever; there is no bulk migration. (3) **Conversion:** between reading an old report and saving it, the app converts: the loaded frontmatter goes through `normalize()` on the way to disk, so an unsigned report becomes current at its next save and a signed one at its next correction (a new revision).
