# CLI reference

The full command descriptions of `CLAUDE.md`, verbatim. Every command answers `--help` (its static `help()`) and prints what it is about to do as its first stdout line; `CLAUDE.md` keeps each command's usage and a one-line summary.

```
bin/reporion integrity:verify [--backup=<dir>] [--json]  the attic zips (every revision, the revlog hash chain), signatures, the state DB (SQLite check, its mirror of the zips), media, page files moved, copied or made by hand, journal, index; exit 1 on a problem
bin/reporion db:recover [--dry-run] [--json]  reporion.sqlite's page rows, revisions and signatures made again from the attic zips (after a lost state DB with no snapshot, or a `mirror_drift`); removes nothing; comments, media names, moves, deliveries and drafts lived only in the DB; CLI only (D54)
bin/reporion index:vectors [--dry-run] [--limit=<n>] [--force] [--json]  Similar reports: each report's de-identified conclusion embedded by the one model of Admin → AI into page_vectors; and each library source's passages (de-identified, cut as Ask the notebook cuts them) into passage_vectors (docs/library.md, phase 7); a cache; unchanged ones not asked again; --limit counts reports and whole sources; --force asks for all again; writes no page
bin/reporion library:add <file>... [--key=<k>] [--tags=<a,b>] [--actor=<u>] [--dry-run] [--json]  articles into the library (docs/library.md): each file's text extracted (poppler, pandoc, LibreOffice), its record read offline (XMP, document info, page 1's layout, DOI/PMID in the text), a private page `library:{key}` with the original in data/sources/; one already there (same file, DOI or PMID) or holding a CNP is skipped
bin/reporion library:import <file>... [--tags=<a,b>] [--actor=<u>] [--dry-run] [--json]  the records of a BibTeX, RIS or CSL-JSON export (Mendeley, Zotero, EndNote) into the library as sources with no file (a later upload of the same DOI or PMID takes the file); one in the library already, with no title or holding a CNP is skipped; at most 500 a file
bin/reporion library:relookup [<key>...] [--tag=<t>] [--all] [--actor=<u>] [--yes] [--dry-run] [--json]  asks CrossRef and PubMed again for sources already in the library, by their DOI or PMID (the identifier only), and OVERWRITES each record's fields with the answer (a field the lookup does not return stays; MeSH terms are added to the tags): it warns and writes nothing without `--yes`; `--dry-run` asks and shows what would change; one revision per source that changed, audited `page.save`; needs `library.lookup` on
bin/reporion library:abstracts [--offline] [--dry-run] [--limit=<n>] [--actor=<u>] [--json]  each library source's abstract page `library:{key}:abstract` where it has none: the record's `csl.abstract` (40 words at least), else PubMed's or CrossRef's for its DOI or PMID when `library.lookup` is on and not `--offline` (the identifier only; the record is not rewritten), else the article's own when its text marks it plainly (`Support\SourceAbstract`); no AI; revisions `system:librarian` (D41); also Admin → Maintenance
bin/reporion library:notices [--all] [--dry-run] [--limit=<n>] [--actor=<u>] [--json]  each library source's DOI or PMID asked of CrossRef and PubMed (the identifier only) for a retraction, an expression of concern or a correction, kept as the source's `notice` (a banner on its card, a mark on its citations on screen); one revision `system:librarian` per change, audited `page.save` `with: notice` and `on_behalf_of`; a source answered within 30 days is passed over, `--all` asks every one; needs `library.lookup` on; also Admin → Maintenance
bin/reporion library:fulltext [<key>...] [--limit=<n>] [--actor=<u>] [--dry-run] [--json]  the free full text of the sources that have a DOI and no file: each PDF Unpaywall lists (the DOI and `library.unpaywall_email` sent), then OpenAlex's copy (with `library.openalex_key`), then Europe PMC's open-access XML (by PMCID), fetched with the web clip's safeguards and read like an upload; needs `library.lookup` on and the address set
bin/reporion library:merge <keep> <from> [--actor=<u>] [--dry-run] [--json]  the source `from` folded into `keep` (D60): its missing fields, tags, file and text move over, every unsigned page citing it is re-cited, it goes to the trash with a redirect to `keep` (a signed page's old key still resolves)
bin/reporion page:move <from> <to> [--actor=<u>]  a redirect from the old path + fixups in unsigned pages: body links, `[@key]` citations of a renamed library page, `reference`, `priors`, `template` / `exams[].template` (not settings, grants or pins: docs/namespaces.md)
bin/reporion pages:repair-paths [--dry-run] [--json]  page files under pages/ that are no page where they are: one moved by hand takes its page along (rejoined by its `pid`, else by its bytes: the row's path, a `move` row, a redirect, the attic zip moved; no revision), one no page is known for is adopted (its bytes revision 1), a copy is left for the owner; one an open journal intent names is left for journal:replay; also Admin → Maintenance; a signed-in lookup of a page file not indexed does the same (FileTree::adopt)
bin/reporion pages:summarize [--actor=<u>] [--dry-run] [--namespace=<ns>] [--limit=<n>] [--overwrite] [--json]  the assistant's one-line summary for unsigned reports with none (no assistant: the conclusion's first sentence); dry run sends nothing (TODO idea 12); `--actor` (optional, default `cli`) is who it runs on behalf of: the revisions are `system:summarizer` (D41)
bin/reporion pages:tag [--actor=<u>] [--dry-run] [--namespace=<ns>] [--limit=<n>] [--overwrite] [--json]  the assistant's 3–5 tags (the `tags` prompt, whole report, Support\TagList) for unsigned reports with none, plus the RADS categories the conclusion states (`rads:birads-4a`, Support\Rads: no assistant, also on tagged reports); dry run sends nothing; `--actor` (optional, default `cli`) is who it runs on behalf of: the revisions are `system:tagger` (D41)
bin/reporion backup:create [--dry-run] [--json]  an archive of data/ + conf/local.php in data/backups/ (D44: for moving an instance and a copy to keep; rsync stays the routine backup), reporion.sqlite as a `VACUUM INTO` copy; also Admin → Maintenance
bin/reporion backup:rsync [--dry-run] [--if-due] [--json]  a dated, differential rsync snapshot of data/ on the machine Admin → Settings → Backup names, over ssh (D49; reporion.sqlite sent as data/snapshot/reporion.sqlite, refreshed first): unchanged files are hard links to the last snapshot, snapshots older than a week or a month are removed there; `--if-due` is the hourly cron line (does nothing unless the schedule is on and the last snapshot is older than its interval); also Admin → Maintenance
bin/reporion backup:restore <archive> [--replace] [--with-conf] [--actor=<u>]  data/ replaced by the archive's (the old kept in data/.pre-restore-<ts>/), then journal:replay, index rebuild, integrity check; only as the owner of data/ (`sudo -u www-data`); CLI only
bin/reporion tags:prune [--max-uses=<1-5>] [--actor=<u>] [--dry-run] [--json]  remove tags carried by at most `--max-uses` reports (default 1) from the reports' frontmatter: one new revision per page, signed reports keep theirs, `rads:*` and the Admin → Tags dictionary are never pruned, nothing is pruned if `data/tags.yaml` does not parse; `--actor` (optional, default `cli`) is on whose behalf: the revisions are `system:admin` (D41)
bin/reporion tags:review [--no-ai] [--actor=<u>] [--json]  proposals to tidy the tags in use (a rule: near-duplicates, a side or spine level; the assistant's `tags-review` prompt on the tag list only, never a report, no tag that may name a patient): written to the run report only, applied by ticking them in Admin → Tags (as `system:admin`, signed reports keep theirs); "never suggest" goes to `data/tags.yaml` `_rejected`
bin/reporion pages:apply-patient-csv --from=<table.csv> --namespace=<ns> [--loose-names] [--actor=<u>] [--dry-run] [--limit=<n>] [--json]  a site's booking table (DATA, NUME, PRENUME, CNP, DATE CLINICE…) → CNP, birth year, sex, indication into blank fields of the reports it names without doubt (name + exact day, one report); the doubtful go to review, an invalid CNP is never written; not in Admin → Maintenance (needs a file); output names pids and table lines only; `--actor` (optional, default `cli`) is on whose behalf: the revisions are `system:importer` (D41)
bin/reporion pacs:link --site=<code> [--actor=<u>] [--dry-run] [--limit=<n>] [--json]  dicom plugin: link a site's unlinked reports to their PACS study (unambiguous CNP/name+day only; signed ones return to draft); also a local pass that fills a blank `device` from the site's `inst:` texts and the kept `pacs_institution` (no PACS asked; signed ones skipped); `--actor` (optional, default `cli`) is on whose behalf: the revisions are `system:pacs` (D41)
bin/reporion ai:prompts-install --profile=<p> [--target=radiology|generic|research] [--only=<id,id>] [--actor=<u>] [--list] [--dry-run] [--json]  make the shipped example prompts (resources/prompts: radiology 20 pages, with the rail's create, conclusion, diagnostic, gaps-traps, urgent, quality, rapno and the system prompt; generic 7; research 21: the library's analyses, Ask the notebook, Studio, flashcards and the audio overview's script, and a rail table naming ask and grammar) pages of an AI profile, never over a page that is there; also Admin → AI; sends nothing to a model
bin/reporion dicom:header <file.dcm> [--values] [--json]  dicom plugin: which report fields one DICOM file's header could start (no pixel data, nothing kept, no index opened); values hidden unless --values
bin/reporion templates:lint [--ns=<templates:…>] [--json]  what the report templates do that the `create` prompt reads badly (Support\TemplateLint: unclosed brackets, ` / ` outside brackets, dashes, brackets in headings, vague choices, the heading shape; FORMATS §3i-b); reads the page files, opens no database, writes nothing; exit 1 when one has a problem
bin/reporion doctor                     config, permissions, sqlite, extensions; fails if `data/reporion.sqlite` is missing beside page files (it never creates one) or SQLite rejects it; fails if `data/settings.yaml` or `data/tags.yaml` does not parse (both read as empty then, and Admin refuses to save over them); warns if an account names a group that does not exist, or an unsigned report has an exam with no template (D48), or AI settings are not in the current shape (old flat `ai.*` keys / `ai.profiles` left in `conf/local.php` or `data/settings.yaml`)
php tools/migrate-v2.php --from=<1.x data> --to=<new dir> [--dry-run] [--json]  the one-off 1.x → 2.0 conversion (D54, architecture-v2 §11): copy and verify, --from only read; then swap the directories by hand, index:rebuild, integrity:verify
```
